Backend:
- packages should be in plural and sub classes are singular


Database:
- JPA entities should be singular
- attribute names should be in camelCase and should be kept minimal
- Primary keys should be named "id" not "tableId"
- Primary keys should be only of type UUID to keep types consistent
- Have bidirectional mapping to foreign tables
- Specify @Column annotation for all attributes
- @Entity, @NoArgsConstructor(access = AccessLevel.PROTECTED), @Getter, and @Setter should be base annotations for entities. Don't use @Data
- To test for instances equality, don't use Object.equals() and instead compare the business keys: Object1.getId().equals(Object2.getId())
- Add helper methods on the weak entity if using bidirectional mapping


Git Commits
- Use Angular Commit Convention ("type(scope): message")
- Message should be descriptive, and succinct
- Scope.
  - For the most part, it should be categorized by package and state the file/s being modified in the message
  - If global relative to a layer (frontend/backend), scope should be layer/file (E.g: backend/pom.xml)
  - If global relative to the whole project, just state the file (E.g: README)
- Types...
- Examples:
  - feat(backend/repository): add CandidateRepository
  - fix(backend/models): add @Enumerated(EnumType.STRING) to Manager.role to show enums as strings
  - chore(backend/pom.xml): add spring-security
  - docs(README): add features section
